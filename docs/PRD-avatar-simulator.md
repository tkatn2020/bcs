## 1. 한 줄 정의

> 안경 쓴 3D 마네킹 아바타를 **직접 드래그**해 누진렌즈의 **모든 광학 변수**(등급·ADD·누진대·VD·경사각·안면각·PD·OH·프레임)를 바꾸고, 그때마다 시야 범위가 실시간으로 변하는 모습으로 **모든 변수를 설명할 수 있는** 몰입형 교육·상담 도구.

## 2. 배경 — 왜 개편하는가

| 기존 (v2) | 문제 | 개편 (v3) |
|---|---|---|
| 도수(S/C/AX) 입력 → 2D 렌즈 왜곡 시뮬 | 상담 흐름과 불일치 — 고객이 자기 도수를 몰라도 등급 차이는 이해시켜야 함 | 도수 입력 제거, **등급 5개 중 탭 선택** |
| "렌즈를 통해 본 장면"의 왜곡 표현 | 시야의 **공간적 범위**가 와닿지 않음 | 3D 공간에 시야 존 볼륨을 직접 표시 |
| 피팅 요소(VD·틸트·PD·OH 등) 미반영 | breezm 차별점인 **맞춤 피팅의 가치**를 설명할 도구 부재 | 피팅 파라미터를 터치로 조작 → 시야 변화 시연 |
| 점수·가격·적응기간 등 정보 패널 다수 | 시선 분산 — 설명 도구인데 읽을 것이 너무 많음 | **전부 제거.** 페이지 전체가 3D 아바타 하나에 집중 |

### 2.1 경쟁 공백 (리서치 검증 완료)

| 제품 | 아바타/3D | 시각화 대상 | 시야존 오버레이 |
|---|---|---|---|
| ZEISS VISUFIT 1000 | 9카메라 3D 두상 디지털 트윈 | 프레임 핏·센트레이션·틴트 | ❌ 없음 |
| Rodenstock DNEye + ImpressionIST | 3D 영상 계측 | 측정 정밀도 (PD·VD 자동 산출) | ❌ 없음 |
| Hoya visuReal / Vision Simulator | iPad 센트레이션 + 1인칭 블러 체험 | 측정값·1인칭 왜곡 | ❌ (1인칭만) |
| Fittingbox (Ditto) | 웹캠 VTO SDK | 프레임 외관만 | ❌ 없음 |
| Essilor Varilux 웹 데모 | 2D 다이어그램 | 시리즈별 존 애니메이션·시나리오 비교 | △ (2D, 아바타 없음) |

**결론**: 업계 1위들도 아바타 = "측정·프레임 핏"까지만. **3D 아바타 위에 누진 시야존을 얹어 피팅 파라미터로 조작하는 도구는 시장에 없음** — 이 PRD의 포지셔닝 그 자체. Essilor 웹 데모의 검증된 UX(존 토글 + 시나리오 + 비교 슬라이더)는 §7 인터랙션의 기본형으로 채택.

## 3. 목표와 활용 시나리오

### 3.1 목표
1. **사내 교육**: 신입 안경사가 **모든 광학 변수**가 시야에 미치는 영향을 아바타 드래그 시연으로 학습 (§8.1 정량 멘트 포함)
2. **소비자 설명**: 등급 차이 + 맞춤 피팅의 가치를 30초 안에 시각적으로 전달
3. **조작 원칙**: 화면 속 아바타·안경을 **직접 만지는 것**이 기본 입력 — 슬라이더·버튼은 정밀 조정과 불연속 값(등급·누진대) 전환용 보조

### 3.2 대표 시나리오
- **S1 (교육)**: 선배가 "OH가 2mm 낮게 조제되면?" → 아바타의 안경을 아래로 드래그하면 근용존 콘이 책(타깃)에 닿지 않는 것을 시연 — *"2mm 오차면 고가 렌즈가 사실상 사용 불능" (ANSI 허용오차가 ±1mm인 이유)*
- **S2 (상담·등급)**: 고객 앞에서 BP10 → BP50 순서로 탭 → 측면 왜곡존이 줄어들고 시야 콘이 넓어지는 변화를 관찰
- **S3 (상담·피팅)**: "저희가 정점간거리·경사각까지 측정하는 이유" → '잘못된 피팅' 프리셋 원터치 → 표준 피팅 복귀 데모 — *"PD 1mm 오차면 독서존이 2mm 좁아집니다"*
- **S4 (교육·자세)**: 아바타 고개 숙임(독서 자세) 토글 → 시선이 렌즈 하부를 통과하며 근용존을 쓰는 원리 시연

## 5. 화면 구성 — 3D 아바타 단일 포커스

### 5.1 레이아웃 원칙 (v2와의 구조적 결별)

- **fit-host 고정 스케일 폐기**: v2의 `scale(sx, sy)` 비균등 스케일은 2D UI에선 무해했지만 3D 구형 두상은 찌그러짐이 즉시 인지됨 (리서치 확인). 3D 캔버스는 고정 해상도가 필요 없으므로 **전체 뷰포트 canvas + 카메라 aspect 대응**으로 전환 — letterbox 문제도 원천 해소
- 정보 카드·사이드 패널 없음 — 3D 뷰포트가 화면을 지배 (아래 ASCII는 시안 수령 전 임시 구조도)
- **비주얼 디자인(색·타이포·컨트롤 스타일·배경)은 사용자 제작 Claude Design 시안이 단일 기준** — 기존 v2 디자인 데이터는 사용하지 않음
- 배경 밝기는 시안에 따름 — 기술 결합 주의: 시야 콘 additive blending은 어두운 배경 전제, 밝은 시안이면 NormalBlending + opacity 재튜닝 (§13)

```
┌────────────────────────────────────────────────────────────┐
│ (얇은 상단) breezm │ [BP10][BP20][BP30][BP40][BP50] │ ↺    │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                 3D 뷰포트 (화면의 ~85%)                     │
│           마네킹 두상 + 안경 + 시야 콘 + 타깃               │
│                                                            │
│   ⟲ 드래그 회전 · 핀치 줌 · 안경 직접 드래그               │
│                                                            │
│  ┌─ 플로팅 컨트롤 (반투명, 접기 가능) ──────────┐           │
│  │ ADD ─●── │ 누진대 ◦●◦ │ 피팅 ▾ │ 뷰 ▾ │ 존 ▾ │           │
│  └──────────────────────────────────────────────┘           │
└────────────────────────────────────────────────────────────┘
```

### 6.2 재질·조명 (광택 흰색 재현 — 기술 검증 완료)

```js
// 마네킹 재질
MeshPhysicalMaterial {
  color: #f4f4f6, metalness: 0, roughness: 0.3~0.4,
  clearcoat: 1.0, clearcoatRoughness: 0.1~0.25
}
```
- **환경맵 필수**: 환경맵 없이는 clearcoat 반사가 죽음 → `PMREMGenerator` + `RoomEnvironment`(three/addons, 절차 생성이라 텍스처 다운로드 불필요)를 `scene.environment`에 지정
- 기존 `lens3d.js`의 3점 조명 rig(warm key + cool fill + rim) 병행 — 하이라이트 형태 조절용

### 6.3 시야 존 시각화 — 3중 표현

| 표현 | 내용 | 역할 |
|---|---|---|
| (a) 렌즈 면 존 맵 | 렌즈 표면에 원용/corridor/근용/측면 왜곡존을 색으로 표시 | "렌즈의 어디가 선명한가" |
| (b) 공간 시야 콘 | 각 존에서 공간으로 뻗는 반투명 볼륨. 원용=수평·원거리, 중간=약간 아래·모니터, 근용=하방 30~40°·독서 | "그 존으로 어디를 볼 수 있는가" |
| (c) 양안 겹침 | 좌·우 콘의 교집합 하이라이트 — PD 오차 시 겹침 축소가 즉시 보임 | "두 눈이 함께 보는 범위" |

- 렌더 규칙 (리서치 검증): `transparent + opacity 0.15~0.3 + depthWrite:false + renderOrder 명시` — 알파 정렬 아티팩트 회피. 블렌딩 모드는 시안 배경에 맞춰 선택 (§13)
- 컬러: **Claude Design 시안 확정 후 결정** — 존 구분 4색(원/중/근/왜곡)은 시안에 반드시 포함될 요소. 시안 수령 전 임시 관례: 원=파랑·중=초록·근=앰버·왜곡=적색

## 7. 인터랙션 카탈로그 (전체 탑재 목표)

**입력 위계**: B군(직접 드래그)이 기본 입력 — 이 도구의 존재 이유. A군 컨트롤은 정밀 조정·불연속 값(등급·누진대·프레임) 전환용 보조.

### A. 렌즈 구성 (보조 컨트롤)

| ID | 인터랙션 | 반응 |
|---|---|---|
| A1 | 등급 카드 5개 탭 | 시야 존 300ms morph (파라메트릭 lerp — §9.3) |
| A2 | ADD 슬라이더 (+0.75~+3.50) | 왜곡존 팽창·corridor 협소 실시간 |
| A3 | 누진대 3버튼 (10/12/14mm) | 존 수직 배치 morph |
| A4 | 프레임 형상 4종 (사각/원형/보스턴/애비에이터) | 안경 3D 교체 + 존 잘림 변화 |
| A5 | B치수(렌즈 세로) 슬라이더 | 작아지면 근용존 물리 잘림 시각화 |

### B. 직접 드래그 조작 (1급 입력 — 이 도구의 존재 이유)

| ID | 인터랙션 | 반응 |
|---|---|---|
| B1 | 안경 **상하 드래그** | OH 변화 — 근용존 도달/잘림 |
| B2 | 안경 **앞뒤 드래그** | VD 변화 — 전 존 시야각 확대/축소 |
| B3 | 안경 **기울임 핸들** (측면 뷰) | 경사각 — 이탈 시 해당 존 축소 + 경고 틴트 |
| B4 | 템플 **벌림 핸들** (위 뷰) | 안면각 — 측면 왜곡존 팽창 |
| B5 | 렌즈 **좌우 간격 핸들** | PD 오차 — 양안 겹침 축소 |
| B6 | 파라미터 라벨 더블탭 | 해당 값만 표준 복귀 (스프링 애니메이션) |
| B7 | **'잘못된 피팅' 프리셋** 원터치 | 모든 파라미터 흐트러짐 → '표준 피팅' 복귀 대비 데모 |
| B8 | 드래그 중 수치 툴팁 | 예: "VD 14mm (표준 12)" 실시간 표시 |
| B9 | **아바타 머리 상하 드래그** | 고개 숙임/들기 — 시선이 렌즈의 어느 존을 통과하는지 실시간 표시 |

구현 규칙 (리서치 검증): `DragControls` 사용 금지 (OrbitControls와 터치 충돌 다수 보고). `pointerdown`에서 Raycaster로 안경 그룹 히트 → 히트 시 `orbitControls.enabled=false` → 이동은 **1축 제한 드래그**(코 능선 경로 등) → `pointerup`에 재활성화.

### C. 카메라·뷰

| ID | 인터랙션 | 반응 |
|---|---|---|
| C1 | 한 손가락 드래그 | orbit 회전 (`TOUCH.ROTATE`, polar 각 제한) |
| C2 | 두 손가락 핀치 | 줌 (`TOUCH.DOLLY_PAN`, pan 비활성) |

## 8. 파라미터 → 시야 영향 모델

### 8.1 조작 범위·영향·교육 멘트 (리서치 정량 앵커, 전 항목 high confidence)

| 파라미터 | 범위 (기본값) | 시야 영향 | 교육 멘트용 정량 앵커 (출처 확보) |
|---|---|---|---|
| 렌즈 등급 | BP10~BP50 (BP30) | 등급↑ → 전 존 폭↑, 왜곡존↓ | Sheedy(OVS 2004/05) 28종 실측: 설계 간 존 폭 편차 2:1 이상 — "같은 ADD라도 설계로 특정 존을 2배 넓힐 수 있다" |
| ADD | +0.75~+3.50 (+2.00) | ADD↑ → 왜곡존 확대, corridor↓ | **Minkwitz**: corridor 유효 반폭 ≈ 0.25×corridor길이÷ADD — "ADD가 2배면 corridor 폭 절반" |
| 누진대 | 10/12/14mm (12) | 짧음: 왜곡 급, 근용 도달 빠름 | ZEISS 공식표: corridor 10mm→근용폭 6mm ... 16mm→15mm — "누진대 6mm 연장에 근용폭 2.5배" |
| 정점간거리 VD | 8~16mm (12) | 멀수록 전 존 축소 | 기하 유도: VD 1mm 증가 ≈ 각도 폭 4% 감소 — "속눈썹이 닿지 않는 한 최대한 가깝게" |
| 경사각 (틸트) | 0~15° (10°) | 이탈 시 존 어긋남·수차 | 2°당 광학중심 1mm 하강. 설계 대비 5° 이상 차이면 보정 처방 권장 (Martin 공식) |
| 안면각 (랩) | 0~15° (5°) | 과다 → 측면 왜곡존 확대 | 적정 5~7°. 설계 대비 5° 이상 차이면 보정 필요 — 스포츠 프레임은 freeform 보정 필수 |
| PD 오차 | -4~+4mm (0) | 좌우 존 오프셋 → 양안 겹침↓ | **"단안 PD 1mm 오차당 독서존 폭 약 2mm 축소"** (20/20 Mag). ADD 2.50에서 1.5mm 편심 → 근용 시야 ~50% 손실 |
| OH (피팅 높이) | -4~+4mm (0) | 존 지도 통째 수직 이동 | 1mm 오차 → 정면 시선이 전이부에 걸림. **2mm → 근용존이 프레임 밖 = "고가 렌즈 사용 불능"**. ANSI 허용 ±1mm |
| 프레임 B치수 | 28~42mm | 작으면 근용존 잘림 | 근용존 최소 세로 5mm 필요 — 피팅높이 18mm면 실용 최대 corridor 13mm. 하단 코쪽 깎인 형상(애비에이터)은 근용 inset 코너를 잘라냄 |

### 8.2 계산 모델 — 단순 곱셈 배율 (정성 + 리서치 앵커)

```
존폭(zone) = 기본폭(zone) × 등급배율 × ADD배율 × VD배율 × 틸트배율 × 랩배율
corridor폭 ∝ corridor길이 ÷ ADD                    (Minkwitz — 리서치 검증)
근용존 잘림 = OH·B치수에 의한 기하 클리핑            (배율이 아닌 마스크)
양안겹침   = overlap(좌존 ± PD오차, 우존 ∓ PD오차)   (1mm ≈ 존폭 2mm 축소로 캘리브레이션)
```

- 배율 룩업 테이블 초안: VD 1mm당 ±4% (기하 유도치 채택), 틸트·랩은 표준 구간 밖 이탈량에 비례한 페널티
- 기존 `grades.js`의 `clearZoneScale`(0.95~1.30)·`cylReductionFactor`(1.05~0.55)를 등급배율 근거로 재사용
- 최종 배율표는 구현 시 초안 제시 → **Joel 임상 검수** 후 확정
- UI 소형 캡션: "교육용 상대 비교" (정량 시뮬레이션 아님을 명시)

### 9.3 기술 결정 (리서치 검증)

| 결정 | 내용 |
|---|---|
| three/addons **self-host** | OrbitControls·GLTFLoader·RoomEnvironment를 로컬 vendor로 복사 — 매장 iPad 오프라인/저속 네트워크 리스크 제거. 마네킹 GLB도 로컬 |
| 존 morph = 파라메트릭 lerp | 존이 파라메트릭 원뿔이므로 지오메트리 재생성 없이 개방각/스케일 lerp — morphAttributes보다 단순, 기존 RAF 패턴과 궁합 |
| WebGL 컨텍스트 관리 | iOS 컨텍스트 상한(~8개, 초과 시 오래된 것 강제 소멸) — 단일 renderer, 모드 전환 시 dispose 필수 |
| 포인터 좌표 정규화 | `canvas.getBoundingClientRect()` 기준 (스케일 자동 보정) |
| 성능 예산 | 마네킹 ≤5만 tri·텍스처 없음, 콘 저폴리, 환경맵은 절차 생성(RoomEnvironment) — iPad Safari 메모리 강제 리로드 예방 |
